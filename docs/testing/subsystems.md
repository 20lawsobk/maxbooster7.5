# Native and imported subsystem tests

Run these commands from the repository root. Results are in
`reports/test-verification/subsystems/results.json`; every command has its own
`.txt` stdout/stderr artifact and an actual exit code. This runner does not
inherit application credentials or use the production database.

## Prerequisites and installation

- Node.js 22.12 or newer, Python 3, C/C++ linker tools, Rust 1.93.1 (`cargo`,
  `rustc`), and Go 1.26.6 (`go`). Rust dependencies are pinned by
  `boosterstate/Cargo.lock`; Go dependencies by the module's `go.mod`/`go.sum`.
- Install root JavaScript dependencies with `npm ci --ignore-scripts`. Install
  imported workspace dependencies with `pnpm --dir external/maxcore install --frozen-lockfile --ignore-scripts` and the same command for `external/pdim`.
- The isolated PDIM HTTP suite additionally needs `initdb` and `pg_ctl`
  (PostgreSQL 17), root `pg`, `drizzle-kit`, `esbuild`, and `tsx` dependencies.
  Run as an ordinary unprivileged user; PostgreSQL refuses initialization as
  root. No Neon URL or external Redis is needed.
- The optional publishing/cleanup test needs `nix-shell`, or pass
  `--rust-toolchain /path/to/verified/portable-rust` for the repository's pinned
  portable Rust distribution. Its verifier needs the intact official toolchain
  and repository verification script.

Add the selected compiler and PostgreSQL directories to `PATH` before running.
Use the environment's configured network proxy and CA trust for downloading
locked dependency packages. `--offline` requires populated Cargo and Go caches;
it does not install missing dependencies.

## Run everything in this group

```sh
python3 scripts/testing/run-subsystems.py \
  --include-rust-concurrency --include-pdim-smoke
```

For a verified portable Rust installation:

```sh
python3 scripts/testing/run-subsystems.py \
  --include-rust-concurrency --rust-toolchain /path/to/portable-rust \
  --include-pdim-smoke
```

Use `--output /path/to/results` to retain another run without overwriting this
snapshot. Optional `--cargo-home`, `--go-path`, and `--go-cache` select reusable
compiler caches. The default cache is `.cache/testing/subsystems/`, which is
excluded from Git. The runner creates a private temporary home and allows only
proxy/CA configuration, library paths and the explicitly selected compiler
settings into subprocesses. Missing executables are `blocked`; command failures
and timeouts are `failed`, with nonzero overall status. Optional suites that are
not requested are absent from the report, not counted as passes.

## Disposable PDIM HTTP/load fixture

Use the scoped Python runner above, or launch this fixture directly with a clean
environment, keeping the chosen `PATH` and required library directory only:

```sh
env -i PATH="$PATH" HOME=/tmp LANG=C CI=1 \
  node scripts/testing/run-pdim-smoke.mjs
```

If the environment uses an extracted PostgreSQL distribution, also pass its
`LD_LIBRARY_PATH`. The wrapper refuses inherited application secret/configuration
variables. It creates a PostgreSQL cluster on a private Unix socket, derives SQL
from the original PDIM schema, bundles the original Express app, initializes
real Redis and fabric storage, and runs the original assertions at an ephemeral
loopback URL. An egress guard permits only loopback/Unix socket traffic. All
server/test processes, the database and the temporary fabric directory are
removed afterward, including failed setup and timeout paths.

The fixture deliberately does not start dataset discovery/download schedulers,
the logical 100-TB corpus metadata auto-push, the process watchdog or external
object storage. `/autopush/status` is tested for its original shape, not proof
that an entire corpus was transferred. Lua uses the application's main-thread
fallback in the CJS fixture. The throughput figures describe this local fixture,
not production capacity, multi-host durability or the standalone full-service
startup path.

`pdim-smoke-results.json`, `pdim-smoke.txt`, `pdim-smoke-setup.txt`, and
`pdim-smoke-server.txt` retain the result and diagnostics. Directly running the
legacy `smoke-load-test.ts` without this fixture uses its `API_BASE` environment
variable (default localhost:3000) and writes/deletes data on that endpoint; use
the disposable wrapper for reproducible verification.

## Discovery boundaries

Tracked source discovery found no dedicated non-Python JS/TS test suite in
MaxCore, dns-node, tls-proxy, the Electron app or the Electron transport package.
Their behavior may be covered by root contract/unit tests documented in the
main catalog; absence of package-local tests is not a pass. `dns-os/package.json`
still has an `echo "No tests yet"` placeholder: it is not executed or counted as
verification. The real Go suite above is run instead.

MaxCore Python tests are in the Python guide. Generated `.pdim-scratch-*`
retained snapshots and benchmark JSON files are not independent executable
suites. This subsystem report establishes only the listed checks, not overall
Max Booster production readiness or deployed Replit/provider behavior.
