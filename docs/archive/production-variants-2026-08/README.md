# August 2026 production build and start variants

This is a read-only historical archive of distinct production build, start,
container, deployment-entrypoint, and closely related documentation versions
found in the Git refs available when the archive was created.

The archive is separate from the active deployment files. It does not change
`build.sh`, `start.sh`, `package.json`, `.replit`, or the current Replit publish
configuration. Historical shell scripts are stored with mode `0644` and are
not approved for direct execution. They may rely on obsolete ports, runtime
layout, credentials, or destructive packaging assumptions.

The archive generator is:

```sh
node scripts/archive-august-production-variants.mjs --write
node scripts/archive-august-production-variants.mjs --verify
```

The default invocation is a dry run. `--write` refuses to replace an existing
archive and first rejects detectable embedded credentials. The manifest records
the original source path, Git blob, observed commit, content checksum, and
pre-archive hashes of the active deployment files. `package.json` is represented
only by its build/start/deployment-related npm script entries, not by historical
dependencies or unrelated configuration.

`--rebuild` is only for expanding an archive generated by this tool. It verifies
the existing checksums and active-file baseline, refuses to drop any archived
variant, then stages the replacement and restores the previous archive if the
directory swap itself fails.

## Scope

The archive includes distinct August versions of the root build/start scripts,
production/development launchers, directly used build helpers, relevant
container and cloud deployment entrypoints, deployment-related npm scripts,
and the launch/deployment documentation that existed or changed in that
month. For historical `.replit` configuration, only the allowlisted
`[deployment]` target/build/run fields are archived; old user-environment
entries are deliberately excluded. An older GCP deployment script is
identified as a separate target; it is not the Replit publishing path.

The current configured Replit workflow remains authoritative. Historical
versions are evidence for comparison and recovery, not proof that a local build
or rehearsal produced a successful published deployment.
