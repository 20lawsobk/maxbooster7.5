---
name: AwarenessProfiler format/compressibility detection gaps
description: A confirmed magic-byte collision bug (fixed) and a known heuristic blind spot (open) in the codec-mesh awareness pre-pass that decides store-vs-compress before codec selection
---

- **CONFIRMED BUG (fixed):** the RIFF container magic (bytes 0-3, ASCII "RIFF") was labeled unconditionally as `"webp"` and treated as already-compressed. RIFF is a generic container shared by WAV (uncompressed PCM audio) and AVI, not just WebP — the real format tag lives at offset 8-11 ("WEBP" / "WAVE" / "AVI "). This silently skipped real compression on every plain WAV file — this app's beat-audio storage format — a real regression for the app's dominant live-storage content type. Fix: require the offset-8 format tag before calling anything "webp"; a bare "RIFF" prefix is not enough.
- **Why this matters generally:** any magic-byte/format-sniffing check must disambiguate on a container format's *inner* type tag, not just its generic outer wrapper — outer-only checks silently misclassify sibling formats. RIFF (WAV/AVI/WebP) is the concrete example found here, but the same mistake class applies to any wrapper format with multiple inner types (e.g. ZIP-based Office/JAR/APK formats sharing one outer signature).
- **OPEN LIMITATION (not fixed — filed as a follow-up task):** the profiler's "already compressed, don't bother" call is based on Shannon entropy over a sampled prefix, which measures byte-*value* distribution, not long-range repetition/redundancy. A buffer with real LZ-detectable redundancy (e.g. a repeated/looped audio segment) can still measure high local per-byte entropy and get wrongly flagged "store", missing compression a real codec would have found.
- Verified with a synthetic worst case (a small chunk repeated byte-for-byte ~200x to ~700KB): before the RIFF fix, entropy+magic-byte both said "store" (~1.00x, worse than doing nothing once container overhead is added); after the RIFF fix let it actually attempt compression, zstd found ~418x.

**How to apply:** don't trust a "store" recommendation as a hard mandate for high-value content paths without at least a cheap empirical check (e.g. trial-compress and keep the smaller of store/compress) — the entropy+magic-byte pre-pass is a fast heuristic, not a verified measurement. See `live-storage-codec-mesh-integration.md` for where this profiler is now wired into real user storage.
