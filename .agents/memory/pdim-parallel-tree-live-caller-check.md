## The trap
`server/pocket-dimension/fabric/` (compression router, codec mesh, container format, storage service with putObject/getObject) is wired into `server/index.ts`'s boot sequence and has no *other* code depending on it — which looks like "the live tree, safe to fix." But being constructed at boot is not the same as being on a real request path. Concrete evidence from one investigation: `server/services/storageService.ts`, `hybridStorageService.ts`, `modelWeightStorage.ts`, and `offlineModeService.ts` (the services real uploads/downloads/model-weights/offline-cache actually go through) all import a completely different, older `PocketDimensionManager`/`PocketDimension` from `server/pocket-dimension/index.ts`, which does its own inline `zlib` gzip-level-9 compression — none of them import the fabric tree at all. A `grep` for importers of the fabric class turned up only its own barrel file.

**Why:** this repo has accumulated several parallel/vendored implementations of the same "pocket dimension / capsule / compression" concept over time (at least: the legacy `server/pocket-dimension/index.ts` gzip path that is actually live for storage services; the newer `server/pocket-dimension/fabric/compression/` engine with zero live callers; and a third vendored copy at `external/pdim/artifacts/api-server/src/pocket-dimension/platform-capsule.js` used only by `script/build-capsule.ts` for deploy capsules). Fixing real bugs in one of them is legitimate and safe, but does not mean production traffic benefits from the fix until something is actually wired to call it.

**How to apply:** before claiming a compression/storage fix is "live" or affects real data, grep the whole `server/` tree for importers of the specific class/module you changed, and trace the boot-log line(s) a running instance actually prints (e.g. "sole storage backend") back to the source file that logs it — don't assume the tree with the most recent/best code is the one every service uses. If a fix sits on a tree with zero real callers, say so explicitly rather than implying production impact; wiring it in is a separate, distinct decision with its own blast radius.
