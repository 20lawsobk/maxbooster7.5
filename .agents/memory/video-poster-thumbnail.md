## The rule
A generated-video job MUST emit a real server-side `thumbnail_url` (an extracted first-frame JPEG), and the client MUST render it as a native `<video poster=...>`. A valid, correctly-served MP4 alone is NOT enough.

**Why:** Even a fully valid MP4 (H.264 Constrained Baseline / L4.0 / yuv420p / faststart, served HTTP 200 `video/mp4`) renders as a grey box at 0:00 on mobile browsers, because with `preload="metadata"` mobile Safari/Chrome do not decode and paint a first frame until the user taps play. Without a `poster` there is nothing to show. The earlier committed workaround appended a `#t=0.1` media fragment to the src to force a frame — iOS ignores media fragments on `<video>`, so it silently did nothing. The encode was never the problem; the missing poster was.

**How to apply:**
- Server: after final MP4 composition, extract one frame with ffmpeg (`-ss 0.1 -i <mp4> -frames:v 1 -q:v 3 <poster.jpg>`) into the same served dir, validate it is a real (>1KB) JPEG, and add `thumbnail_url` to the job result. Make it best-effort (try/catch → null on any failure) AND bound the subprocess with a kill-timeout (a hung ffmpeg must never stall job completion). Guard the URL→local-path mapping on the known served prefix (`/uploads/videos/`) before resolving into the ffmpeg input.
- Client: render generated clips through one reusable native `<VideoPlayer>` (native `<video>` with `poster`, `controls`, `muted`, `playsInline`, `preload="metadata"`; internal `onError` → honest fallback). Do NOT use `#t=0.1`. Do NOT use a `<source type="video/mp4">` child — see `video-blob-mime-type.md` (blob URLs may be WebM; a declared mime mismatch silently rejects the source). Thread the job's `thumbnail_url` into the player's `poster`.
- Only render the player where `src` is truthy (guard on the media URL) so `poster` decorates a real video.

## Two more seams the poster silently drops on (found after the /generate-video fix)
The `/generate-video` job emitting `thumbnail_url` is necessary but NOT sufficient — the poster is lost anywhere a component computes it internally but hands only the URL up, or where a job's completion contract omits it:

- **Social "Generate from URL" → `ServerVideoGenerator` handoff.** When URL-gen returns no video asset, the client injects a synthetic item and renders `ServerVideoGenerator`, which DOES compute its own `posterUrl` (from `data.thumbnail_url`) and previews correctly. But its `onVideoGenerated(url)` callback only carried the URL, so the parent set `mediaUrl` and rendered `<VideoPlayer>` with NO poster = grey box. Fix: the callback signature must be `(url, posterUrl?)` and the parent must persist `posterUrl` on the item. Any "child renders fine but parent handoff loses the poster" is this same class.

- **Distribution music-video job contract.** The `/generate-music-video` job (both the MaxCore studio branch AND the legacy image branch) did NOT extract a poster, and `GET /music-video-job/:jobId` returned `status:"done"` with the URL nested at `result.url`, while the client waited for `status:"completed"` and read `data.videoUrl` — so it never displayed at all. Fixes: (1) extract the poster in BOTH done branches via the (now-exported) `generatePosterThumbnail` from `advancedVideoRendererService`, attaching `thumbnail_url` to the result; (2) the GET route normalizes to `status:"completed"` with flat `videoUrl`+`thumbnailUrl` (keep `result` for compat) and returns the error branch as **200 `status:"failed"`** (a 500 makes a `try/catch`-wrapped client poll swallow it and poll forever); (3) client sends the flat FormData fields the route actually reads (the `config` JSON blob was never parsed server-side) and renders `<VideoPlayer src poster>`.
  - **MaxCore routing for that page:** send `ai_generate_scenes="true"` when audio is present → routes to the MaxCore Music Video Studio (AI-generated scenes, ignores uploaded images); image-only (no audio) → legacy local ffmpeg. The Generate button's `disabled` gate must match the handler's validation (audio OR images), or the audio-only MaxCore path is unreachable from the UI. Legacy voice narration reads `body.voice_text` — guard it (`?.trim()`) AND have the client send a `voice_text` script, or enabling voice throws on `undefined.trim()`.
