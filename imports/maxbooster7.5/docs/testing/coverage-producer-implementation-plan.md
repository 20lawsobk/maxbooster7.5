# Source-mapped coverage producers: implementation plan

Recorded October 27, 2026. This is a read-only design produced during the final
master's source freeze. No runner, runtime, test or configuration is changed by
this document. The goal remains **100% of lines, statements, functions and
branches across the existing platform denominator**, together with every named
feature's acceptance checks. Reusing existing real execution avoids unnecessary
duplicate behavioral cases; it cannot substitute for genuinely missing behavior.

## Observed position

The current global profile contains 2,651 files and measures approximately
13.11% lines, 13.01% statements, 8.67% functions and 8.79% branches. Passing
instrumented assertions do not measure the separate Node/application/browser
processes. The master also runs 112 Node files and separate HTTP/browser
journeys. Their behavior can provide additional coverage only after retaining
and validating their actual executed JavaScript, source maps and raw counters.

Observed producer boundaries:

- `scripts/testing/common.py:clean_environment` deliberately creates a small
  environment; an ambient `NODE_V8_COVERAGE` is dropped. Its `run_command` can
  supply a narrowly chosen `extra_env`, but currently the Node runner does not.
- `scripts/testing/run-node-suites.py` runs each selected Node file separately
  with `node --import tsx`, then records TAP outcomes. It supplies no coverage
  producer. A file's tests can also bundle/import subjects or spawn children.
- `tests/payment-processing/helpers-database-postgres.mjs:loadDatabaseSubject`
  bundles with esbuild into a temporary `subject.mjs`, uses explicitly replaced
  boundaries, imports it, then removes the directory in `finally`. It currently
  does not request a source map or retain the generated code. A later coverage
  process cannot safely reconstruct these deleted runtime bytes from the
  original TypeScript. PostgreSQL's own `minimalEnvironment` is intentionally
  separate and should not receive JavaScript coverage settings.
- `scripts/testing/integration-browser.mjs` first rejects inherited application
  credentials, then constructs a new `env`, `common`, application environment
  and test-worker environment. An ambient coverage variable is dropped again.
  The server is a separate `server/index.ts` process loaded through `tsx`; the
  Vitest HTTP driver's coverage would not measure that server. Application,
  worker and fixture-child producers need separate identities. Keep the egress
  guard, fixture database proof and private disposable state unchanged.
- `scripts/testing/page80-acceptance.mjs` likewise creates controlled application
  and browser environments and starts a separate source application. Chromium
  does not produce JavaScript coverage merely because `NODE_V8_COVERAGE` exists.
  Its CDP targets/contexts need an explicit precise-coverage producer.
- Existing Node/browser test files and helper functions may construct additional
  allowlisted child environments or esbuild outputs. Inventory those exact
  boundaries before rollout; setting one outer variable is insufficient.

Installed conversion versions are `@vitest/coverage-v8` **4.1.12**,
`ast-v8-to-istanbul` **1.0.7**, and the installed `@bcoe/v8-coverage` and Istanbul
packages from the current lockfile. Vitest's provider calls
`astV8ToIstanbul({code, sourceMap, ast, coverage, wrapperLength, ignoreNode})` on
its **executed transformed JavaScript**. It uses provider-specific handling of
SSR imports/exports, import-meta and generated constructs. Browser/SSR project
transforms are intentionally separated. Its `getSources` fallback can construct
dummy slash code when a runtime file has disappeared; a new external producer
must instead fail when actual generated bytes are unavailable. Never adopt that
fallback to manufacture external evidence.

## Small implementation batches, in dependency order

### P1: compatibility and provenance spike before wider reruns

Add `scripts/testing/coverage-provenance.mjs` and
`tests/testing/coverage-provenance.test.mjs`. Implement strict manifest,
artifact/source/map validation and an exact per-file map comparator first. The
manifest includes producer/run IDs, command, actual exit, source-input digest,
Node/V8 or Chromium version, converter/parser versions and options, generated
script bytes/map hashes, original source hashes, fixture-boundary definitions,
wrapper offsets, snapshot reset/sequence semantics and cleanup status.

Compare retained Studio artifacts without rerunning behavior. Reject today's
incompatible statement maps. Then select **one** existing small Node suite that
imports a real unbundled production subject, and one existing bundled SQL suite.
Collect actual code/maps/counters using P2/P3 and compare all three converted maps
against a same-source canonical profile. Do not roll out to 112 files until this
proves valid, repeatable results or identifies the exact transform differences.
This compatibility test is the first deliverable; no percentage increase is
promised by the design.

Acceptance: valid raw manifests are accepted; source/bundle/map drift, missing
runtime code, missing original source, parse/exclusion warnings and incompatible
maps fail explicitly. Existing profiles remain intact. Any deliberate converter
option must be versioned and applied consistently to the whole participating
profile, not chosen per file to remove unhit constructs.

### P2: one isolated Node producer

Add `scripts/testing/coverage-node-bootstrap.mjs`. Extend
`scripts/testing/run-node-suites.py` with an opt-in, explicit output directory,
not ambient environment inheritance. Use `common.run_command(..., extra_env=...)`
to pass only a validated absolute per-run coverage directory and producer
manifest selector. Load the known repository bootstrap through explicit Node
arguments before subject imports; do not allow inherited arbitrary `NODE_OPTIONS`.

For plain executed JavaScript, retain exact runtime bytes. For `tsx`/VM-generated
scripts, the bootstrap must capture actual `Debugger.scriptParsed` identities,
`Debugger.getScriptSource` text, the corresponding inline/external source map and
raw ranges; do not recompile original TypeScript later and apply old offsets to
new code. Node's `NODE_V8_COVERAGE` can preserve process JSON and source-map cache,
but a source-map cache/line-length list alone is insufficient input to the
AST-aware converter: it does not establish the actual generated code's AST.
Retain raw Node output as corroborating evidence, or use a single well-defined
inspector snapshot lifecycle as the authoritative producer. Avoid collecting
and summing both representations of the same execution.

Use process/worker-specific child directories. Check each V8 offset against its
actual JavaScript string length in UTF-16 code units and preserve explicit VM/CJS
wrapper offsets where present; demonstrate those offsets with fixtures rather
than guessing from original-source positions. Capture child exit/flush status.
A killed or unflushed child is incomplete evidence, even if sibling tests pass.
Flush/await artifact retention before the owned process tracker removes its tree.

The safe selector is an output path, not an application credential. Resolve it
beneath an owned report directory, reject traversal, symlink escape and overlap
with source/private state, create private output permissions and preserve raw
hashes. A fixture which intentionally creates a clean child environment must
copy only this validated producer selector when that child executes JavaScript.
Do **not** broaden `clean_environment` to inherit application/provider values.
Do not pass coverage settings into `initdb`, `pg_ctl`, Redis or other unrelated
native subprocess environments.

### P3: retain bundled SQL subjects before deletion

Extend `loadDatabaseSubject` in
`tests/payment-processing/helpers-database-postgres.mjs` only when coverage is
explicitly selected. Request esbuild source maps and original sources, retain
`metafile`/entry identity and archive output JavaScript plus map before `finally`
removes the temporary bundle. Preserve existing isolation, boundary overrides,
`define` options, target, ESM banner and test semantics. Return/expose the archive
identity through the producer manifest without changing the subject's public API.

Archive each generated subject by generated-code hash and test/fixture identity;
never let multiple temporary files overwrite a shared `subject.mjs` artifact.
Resolve every map source to a canonical repository path and verify its exact
UTF-8 original content hash. Namespace-replaced fixture code remains fixture code:
it cannot credit the production implementation it substitutes. Bundled package
sources are inventoried separately and cannot silently enter or leave the
existing application denominator. The same rules apply to other Node suites'
esbuild helpers, one helper at a time after the first producer passes.

### P4: collect the actual isolated HTTP server

Add the producer to the application `spawn` in
`scripts/testing/integration-browser.mjs` with its own validated directory and
explicit bootstrap argument. Keep the application's output separate from Vitest
workers, MaxCore/PDIM children and setup tooling. Preserve the disposable
PostgreSQL URL and fixture secrets created by the wrapper; forward no real
credential. Capture loaded source/compiled code before the app is terminated.
Explicitly flush before normal owned shutdown and record failure if shutdown
interrupts final collection. Propagate the selector only at inspected JavaScript
child boundaries, retaining each child's identity and egress constraints.

Run the existing targeted HTTP fixture unchanged, validate real server coverage
and map compatibility, then run all existing HTTP suites. This adds measurement
of their executed backend behavior; it does not mark unexecuted routes or provider
callbacks covered and does not certify deployed delivery.

### P5: collect actual browser and page-journey code

Extract reusable CDP collection into
`scripts/testing/coverage-browser-producer.mjs`, retaining the Studio producer's
identity, UTF-8 and navigation checks. Integrate first into its existing browser
case, then each browser runner and `page80-acceptance.mjs` without changing
assertions, omitting routes or substituting screenshots for behavior.

Start precise coverage before navigation/application execution. Capture every
owned relevant page/context and worker target, including new windows and reloads;
record unsupported/missed targets rather than pretending complete collection.
Capture before context destruction and at final completion with explicit
counter-reset semantics. Merge V8 ranges only from non-overlapping snapshots of
byte-identical scripts. Avoid counting cumulative snapshots twice.

For Vite/production assets, retain the exact uncompressed JavaScript executed by
Chromium and its map, including original source content. If assets are gzip or
Brotli encoded, separately hash stored encoded bytes and the decoded executed
text; do not compare encoded file hashes with CDP's decoded script or use offsets
against compressed bytes. A URL/content filename alone is not code identity.
Hash CDP text under its recorded UTF-8 encoding, verify it matches the exact
served decoded script and map, and record the actual browser engine version.
Do not generate a new post-test source map and assume it matches a prior bundle.

### P6: strict conversion and compatible combination

Add `scripts/testing/convert-source-coverage.mjs` and
`scripts/testing/merge-source-coverage.mjs`. The converter consumes only validated
retained runtime code/maps/ranges, uses the pinned AST-aware API and records its
parser/options. It never parses original TS as though it were executed JS. All
source-map/parse/exclusion errors become evidence failures, including exit-zero
logs. Preserve raw inputs and the unmodified per-producer converted profile.

Group raw V8 snapshots by canonical script identity **and generated-code hash**
before `mergeProcessCovs`; normalize ephemeral URLs only after verifying those
identities. Two scripts with the same URL but different code are distinct. Map
original paths inside the repository and validate sourcesContent/current hashes.
Do not merge old source revisions/configuration profiles just because a single
file path matches. Require current participating source/config digests and exact
per-file source hashes; record controlled producer differences explicitly.

For each overlapping original file, compare the complete statement, function and
branch map structures, location order, branch arities and instrumentation policy.
Treat IDs as identifiers of those validated maps, not positions to transfer hits.
If maps differ, retain both profiles separately and fail the combination gate.
Do not union different maps, invent canonical hit ranges or salvage selected
metrics as a full-file pass. Align transforms/options through a separately
reviewed reproducible change, regenerate original execution evidence as needed,
and prove exact equality first. If that cannot be achieved without a larger
canonical compilation change, keep separate measured scopes and continue C1–C4
behavior work instead of forcing an invalid percentage.

Once exact compatibility is established, use Istanbul's normal merge for the
validated profiles; deduplicate producer IDs/raw snapshot hashes to prevent
reusing the same run. Keep every file and zero-hit counter from the existing
canonical full-source denominator. Generate combined JSON/LCOV, exact missing
counters, provenance and all four 100% threshold decisions, while preserving the
original failed/uncombined profiles. Threshold success never overrides a failed
behavioral test or unverified feature/deployment gate.

### P7: integrate and rerun from a new stable source freeze

Only after P1–P6 pass, update `scripts/testing/run-all.py`,
`scripts/testing/summarize-results.py` and the source register/remediation readers
to consume the combined profile and report producer completeness/compatibility.
Keep behavioral outcomes, source integrity, collection/conversion status,
coverage thresholds and feature-contract acceptance as separate gates. Retain
fresh commands and all raw artifact hashes in documented reports. Run the master
from stable source; do not alter instrumentation/configuration while that run is
executing. Broaden producers by helper/runner family after each first case passes,
then add new behavior only for the actual remaining missing branches/features.

## Required regression cases

Use small owned fixtures to verify the framework, not tests that only assert
implementation strings. Include exact runtime JS with branches/functions, a TS
source map with non-ASCII/astral characters, a CJS/VM wrapper, identical reload
snapshots, differing code served at the same URL, a bundled original module,
replaced fixture module, child process, worker and source that remains uncovered.

Reject stale original content, changed generated bytes, changed maps, incorrect
charset, missing sourcesContent, external/traversal source paths, disappearing
runtime bytes, mismatched converter options, incompatible statement/function/
branch maps, wrong branch arity, out-of-range offsets, duplicated/cumulative
snapshots, missing/killed child collection and parse/exclusion warnings. Confirm
an unused original file remains zero-hit and in the denominator. Confirm exact
current compatible maps merge correctly and incomplete/incompatible evidence
cannot raise a reported global percentage. Confirm production credentials remain
absent and existing fixture egress/ownership/cleanup guards still operate.

## First next action after the frozen master completes

Implement **P1 plus one P2 producer**, then make a concrete compatibility decision
before touching all runners. The existing Studio proof already demonstrates that
matching source hashes and a common converter package are insufficient. This
sequence saves repeated behavioral work while preserving the meaning of the
requested platform-wide 100% target.
