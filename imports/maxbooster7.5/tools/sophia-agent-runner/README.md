# Sophia — OpenAI Agents API curl runner

A cross-platform CLI for launching and interacting with the **saved** Sophia agent. HTTP requests use the **curl** executable directly; Python 3.10+ standard library handles JSON, streaming SSE, pending actions, and errors. No OpenAI SDK or Python package install is required.

## Requirements

- `curl` on PATH; Python 3.10+; internet access; an API key with access to the OpenAI project **proj_oFzzFFQDxMXQXnTjy5O7jYMX** and saved agent **agent_762a628c80f34c498937fde62f6b0a7e3c747065dea5426691**.
- The saved agent's GitHub MCP credentials must be valid. This runner explicitly clones the public target repo into the OpenAI-hosted sandbox with `setup_commands`, but write access is handled via the saved GitHub MCP connection; clone access does **not** prove authenticated push access. The launch message requires Sophia to verify access before changes.
- The saved tool named `begin_prod_hardening_for_max_booster` has a placeholder `Placeholder1` parameter and no functional executor provided. The runner safely reports this function as unimplemented rather than falsely claiming it hardened the repo. Built-in hosted command tools and GitHub MCP are handled by the Agents service, not executed locally.
- The OpenAI-hosted sandbox supplies the agent's runtime/executor, prepares a shallow, partial Git checkout of the exact Max Booster GitHub repository in `/workspace/maxbooster7.5` and verifies the repository origin and commit before Sophia starts. This checkout is separate from Replit, and Sophia never invokes the Replit Agent. GitHub MCP handles authenticated branch/PR operations; the sandbox shell tests local changes. A checkout or tool failure blocks execution instead of silently switching to an indirect agent.

## Setup

Keep the secret out of source code, logs, shell history and Git. Configure it in a shell/session secret store:

```bash
export OPENAI_API_KEY='YOUR_PROJECT_AUTHORIZED_KEY'
bash sophia.sh doctor
```

**Windows:** use WSL or Git Bash with `python3` and `curl`. **Android:** Termux + `pkg install python curl`. **macOS/Linux:** use a terminal with Python and curl. The agent's work runs in an OpenAI-hosted sandbox, so your device only controls the session.

If you don't have a key, create a project-authorized key using the OpenAI Platform and configure it as `OPENAI_API_KEY`. Restrict permissions and rotate any key previously pasted into chat.

## Run

```bash
bash sophia.sh dry-run                               # show exact request JSON; no network/key needed
bash sophia.sh start                                 # starts Sophia with initial Max Booster message and live SSE output
bash sophia.sh start 'Inspect the Max Booster repo.'  # alternate first message
bash sophia.sh status sess_YOUR_SESSION_ID           # retrieve authoritative saved status
bash sophia.sh follow sess_YOUR_SESSION_ID 'Proceed with the next verified patch.'
bash sophia.sh watch sess_YOUR_SESSION_ID            # stream existing active turn
bash sophia.sh --events-json start                   # raw JSON event objects
```

The runner prints the session ID when available. Save it for follow-up sessions. It treats `turn.completed` for the **root** turn as success and refuses to mark `idle`, failures, cancellations, or incomplete streams successful. If a stream disconnects, retrieve status before resubmitting input; retries should reuse the same idempotency key for a single submission.

## Underlying direct curl API calls

The actual runtime wraps these HTTP calls with curl and adds JSON/event handling:

```bash
# The session create payload is generated by bash sophia.sh dry-run.
bash sophia.sh dry-run > /tmp/sophia-session.json
curl --no-buffer --fail-with-body https://api.openai.com/v1/agents/sessions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H 'OpenAI-Beta: agents=v1' \
  -H 'OpenAI-Project: proj_oFzzFFQDxMXQXnTjy5O7jYMX' \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/sophia-session.json

# Listen for events for an existing session:
curl --no-buffer --fail-with-body \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H 'OpenAI-Beta: agents=v1' \
  -H 'OpenAI-Project: proj_oFzzFFQDxMXQXnTjy5O7jYMX' \
  'https://api.openai.com/v1/agents/sessions/sess_YOUR_SESSION_ID/events?stream=true'
```

`start` sends `agent_id` plus **only** these unsaved overrides: `model`, `instructions`, `reasoning`, and `text`. This intentionally retains saved `tools`, `multi_agent`, MCP credentials and other saved settings. Arrays/objects supplied as overrides replace whole fields, so the full nested reasoning/text structures are included. The raw `text.format` schema follows the supplied configuration; API validation errors will be surfaced, not silently rewritten.

## Tool calls and error safety

The runner retrieves `required_actions` when the API requests it. For pending function calls it submits `agent.session.input.tool_result` with real `turn_id` and `call_id`, and marks unknown or placeholder functions **unsuccessful**. To give `begin_prod_hardening_for_max_booster` actual functionality, define valid strict parameters and a verified executor in `scripts/sophia.py:tool_result` **or remove/replace the function in the saved agent**. The app never executes arbitrary tool-supplied commands or applies patches merely because an LLM requested it. `environment_connection` and other manually authorized actions are surfaced for you to complete.

For real codebase hardening, confirm the GitHub MCP connection can write to `20lawsobk/maxbooster7.5`, check the actual branch, review changes and test evidence. The checked-out `/workspace/maxbooster7.5` repository in the OpenAI-hosted sandbox is the source Sophia operates on, not your Replit working directory. The session uses a `large` sandbox because this repository is substantial; API usage and sandbox compute are billable. No Replit Agent is involved. If the host checkout fails, reduce or adjust repository fetch scope after inspecting the error rather than claiming success.
