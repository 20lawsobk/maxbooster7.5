Endpoint-only security and functionality audit

Evidence gathered October 6, 2026. Public HTTP only; no application source, database, internal RPC, provider console, or private service was inspected. All requests in this audit were GETs. No releases, payouts, payments, or publishing operations were triggered.

Verdict: incomplete; readiness cannot be approved. Production returned Replit’s “This app isn’t live yet” 404 page for every probe. The preview intermittently responded, then began returning 502s. Consequently the authenticated and state-changing surface could not be comprehensively audited.

2. Security findings

  • Positive but narrow: unauthenticated GETs to the sampled distribution-release, analytics, admin, admin-dashboard, and royalties paths received 401 JSON once. This does not test tampered/expired session handling, authenticated authorization, cross-user object access, or other verbs.
  • Investigate: GET /api/auth/me returned 200 while unauthenticated. The body was not retained, so this is an ambiguous response—not a confirmed disclosure. Verify that an anonymous response contains no user identity or private account fields.
  • Unverified: input validation, role separation, cross-account isolation, CSRF enforcement on writes, sensitive-data leakage on successful account requests, and rate limits.

3. Functionality findings

Health returned 200 once while readiness returned 503. Later preview requests returned 502. This demonstrates that a liveness response is not a readiness pass and the target was not stable enough to exercise normal user workflows. No release, catalog, analytics, or payout workflow was completed.

4. Provider isolation findings

Unverified: public GET responses do not establish that Too Lost is the only active distributor or that LabelGrid cannot run on a submission path. No provider submission or other external write was made. These claims cannot be verified from the observed anonymous responses.

5. Historical data integrity findings

Unverified: no historical LabelGrid record was read. No data was written or deleted by this audit; preservation, identifiers, royalties, tags, and exports remain untested.

6. Runtime stability findings

  • Production: the homepage and nine additional discovery/health probes returned HTTP 404 with the platform page “This app isn’t live yet.” The app runtime was not reached.
  • Preview: early HTTP requests reached application responses; later HTTP requests to admin, distribution, analytics, royalties, and auth paths all returned 502. Headless Chromium also received 502 for the preview homepage. The preview therefore could not support stable end-user verification.
  • Build, capsule restore, module resolution, and readiness after startup are not provable through these HTTP observations. No publish or restart was triggered.

7. Adversarial findings

Invalid-bearer and malformed-query GET probes reached 502 rather than an application response. They establish no validation or token-rejection behavior. Large request bodies, repeated submissions, mutation endpoints, and rate-limit behavior were not tested. No fuzzing or write requests were sent.

8. Final readiness verdict

Not ready for audit sign-off. The published site did not serve the app, and the selected preview became unavailable. The sampled anonymous 401s are limited positive evidence, not a full security pass. Authentication, authorization roles, functionality, provider isolation, historical-data integrity, and adversarial write handling remain unresolved.

To finish this audit, a stable public target and usable route/API documentation are needed. Authenticated tests require a working ordinary test account and, for admin-boundary checks, a separate known-role test identity. State-changing tests additionally require isolated disposable records. Until then, report the above as partial endpoint evidence, not complete project coverage.
