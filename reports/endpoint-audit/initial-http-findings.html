Endpoint-only security and functionality audit

Evidence gathered October 6, 2026. Test scope: public HTTP only. No application source, database, internal RPC, private service, or provider console was inspected. All audit requests were GETs. No release, payout, payment, provider submission, publish, or restart was triggered.

Verdict: partial audit; project-wide sign-off withheld. The preview is currently responding with HTTP 200 on its homepage, health, and readiness endpoints. Production at maxbooster.replit.app still returns Replit’s “This app isn’t live yet” HTTP 404 page. The API discovery paths fail to provide a usable schema, and authenticated workflows remain untested.

2. Security findings

  • Confirmed information exposure — readiness: public GET /api/ready returns a large JSON document with internal subsystem/latency fields. Four values in latency.slowestEndpoints matched absolute server filesystem paths. The exact path values were not retained. The response also includes a buildId; whether this identifier is intended to be public is not established.
  • Confirmed error-detail exposure — API-doc probes: GET /openapi.json and GET /swagger.json return 500 HTML pages. A redacted response scan detected source filesystem paths and stack-trace signatures. Exact paths and trace contents were not retained.
  • Positive, limited evidence: the sampled distribution-release, analytics, admin, admin-dashboard and royalties GETs returned 401 both without a token and with an invalid bearer value. This does not test valid or expired sessions, authenticated roles, cross-user objects, or other HTTP methods.
  • No anonymous identity in sample: unauthenticated /api/auth/me returned JSON null.
  • Security headers present: the preview root and sampled endpoints carried HSTS, CSP, X-Content-Type-Options and X-Frame-Options headers.
  • Unverified: login success, expired/tampered session handling, regular-user/admin separation, cross-account access, write-request CSRF enforcement, provider-secret leakage, and rate-limit thresholds.

3. Functionality findings

Preview liveness and readiness now both return 200, correcting the earlier transient 503 observation. The published domain remains unavailable. The Swagger UI page loads, but the tested specification URL returns HTML and the common OpenAPI/Swagger JSON paths return 500, preventing a complete route map. Normal authenticated user flows were not completed.

4. Provider isolation findings

Unverified: these public GETs cannot establish that Too Lost is the sole distributor or that LabelGrid cannot be invoked through an authenticated submission path. No provider request or write was made.

5. Historical data integrity findings

Unverified: no historical LabelGrid record was read. No data was written or deleted by this audit. Historical IDs, tags, royalty values and exports were not checked.

6. Runtime stability findings

  • Published origin: the homepage and tested API/discovery paths return HTTP 404 with the platform page “This app isn’t live yet.” This does not reach the application runtime.
  • Preview: the final checks found homepage, health and readiness HTTP 200. Earlier readiness 503 and intermittent HTTP 502 responses show the preview was not stable throughout the audit.
  • Build, capsule restore, module resolution and post-start artifacts are outside what these HTTP responses can establish. No build, publish or restart was initiated.

7. Adversarial findings

Unauthenticated requests with no token and invalid bearer values received 401 on the sampled protected GET paths. One traversal-like query reached the same 401; a later malformed query received 429 after the combined audit burst. No malformed request body, oversized payload, repeated release submission, token-expiry case, or mutating request was sent. Consequently validation and duplicate-prevention behavior remain untested.

8. Final readiness verdict

Not ready for project-wide audit sign-off. The observed anonymous auth gates generally reject missing and invalid bearer credentials, and /api/auth/me returns null anonymously. But public health output leaks filesystem paths; common API-schema routes expose stack/path signatures; production remains unpublished; and valid-login, role-boundary, distribution, catalog, analytics, historical-data and write-path behavior remain unverified.

Because the Swagger JSON endpoint is unavailable and this audit is restricted to public HTTP, this report does not claim to enumerate every application route. Completing the audit requires a stable target, working public API documentation, and a normal test account for read-only authenticated checks. Mutating checks require disposable test records.
