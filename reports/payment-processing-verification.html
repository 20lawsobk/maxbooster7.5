Remaining reproducible production failures

  1. Legacy billing retries create duplicate Checkout sessions. Same client command produced two provider creates rather than one.
  2. Storefront cart retries create duplicate sessions and orders. Same command is not durably reused.
  3. Legacy BeatService completion accepts an unverified PaymentIntent ID. Its isolated completion function recorded a sale without authoritative successful-payment verification. This is distinct from the tested canonical marketplace settlement path.

These assertions remain failing in tests/payment-processing/inbound-known-failures.mjs, which the runner includes. They were not suppressed, skipped or relabeled as successful.

Production-strengthening fixes made

  • Withdrawal retry identity now includes the immutable Connect destination; changed-account and missing legacy account bindings fail closed. SQL concurrency verified one immutable winner.
  • 3-D Secure confirmation validates the authenticated customer's PaymentIntent before confirmation or secret-bearing response.
  • Successful PaymentIntent confirmation alone no longer writes active subscription entitlement. Verified billing/webhook processing retains that responsibility.
  • Membership tier create/update/delete require storefront ownership. Tier updates cannot change the parent storefront to bypass that boundary. Actual-handler denial, same-parent owner success, missing-record and reassignment regressions pass.

Provider/account blockers

  • Automatic tax requires a valid test-account head-office address.
  • Express dashboard login link requires completed onboarding.
  • The owned Express test account's transfer capability is inactive and payouts are disabled. Provider transfer/reversal/bank-payout success is therefore unverified, although payload and SQL state-machine contracts passed.
  • Non-Stripe payment preferences/unsupported adapters are not treated as working payment integrations.

Cleanup and safety

Only the explicitly named STRIPE_TEST_SECRET and STRIPE_TEST_CLIENT were used for remote tests. Test formats and authoritative livemode: false were checked. Enabled-webhook inventories were fully paginated before fixture writes. No live charge, application listing, Beat Money Loop run, social publication or shared application database write was intentionally performed.

The browser success charge was refunded and the declined intent canceled, with exact ownership verification. Disposable SQL was isolated on a local Unix socket. Newly journaled Checkout sessions were expired, test customers deleted and explicitly created mutable catalog fixtures deactivated.

Cleanup is not fully certified: provider-immutable paid invoices, automatically generated prices/products, expiring links and the owned dispute fixture remain as test history. Some prior refund associations and an earlier unjournaled handler run cannot be independently reconciled. Reports keep those uncertainties; no broad account cleanup or unowned resource mutation was used. Ownership manifests now survive failed credential/provider preflight.

Operational verification limitations

Targeted ESLint: zero errors, one pre-existing billing warning. Syntax and patch checks passed. A full server typecheck did not finish; the application workflow is currently stopped after that resource-heavy attempt. It was not restarted because startup could trigger production-backed schedulers. The source fixes are verified in isolated tests, not asserted active in the stopped application.
